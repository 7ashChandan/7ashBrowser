# Security Policy

## Supported versions

The repository's latest released version receives security fixes. Development builds are not guaranteed to be supported.

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in public issues.

Include:

- A description of the vulnerability
- Affected version or commit
- Steps to reproduce
- Potential impact
- Suggested mitigation, if available

Contact the repository owner through the private channel listed in the GitHub repository profile. If no private contact is available, open a clearly titled discussion only after removing sensitive reproduction details and wait for an owner to establish a private response channel.

## Secret handling

Never include API keys, access tokens, passwords, cookies, private URLs, or personal data in reports or source code.
